# Degup: design decisions

Public record of the decisions that shape this repo. Each entry: what was decided, why, and how to undo it.
Internal build notes (in Malay) are kept outside the public repo.

| # | Decision | Why | Undo |
|---|---|---|---|
| 1 | Degup is a heartbeat perception game: watch, feel, then bend your breathing | A short, playable question ("Can you feel your own heartbeat?") that shows the SDK signal reacting live | A count mode if the live signal is too sparse |
| 2 | Electron desktop app; the SDK runs on the user's laptop | The SDK's official Node path, with an official Electron sample | A web build only if the desktop path cannot work |
| 3 | Beat times come from `cardio.arterial_pressure_trace` with an in-repo peak detector | The SDK payload has no per-beat marker | A count mode that uses only the rate |
| 4 | The sync score is phase consistency (circular statistics), not delay or a tap count | A steady offset between beat and tap does not matter; consistency does | Show the plain n/N ratio instead |
| 5 | Three scenes, SEE first | The live signal is visible in the first seconds of a session | Reorder scenes with a new entry here |
| 6 | Only cardio and breathing metrics; no face, expression or EDA metrics; no Insights request | The game does not need them | None |
| 7 | Telemetry off; automatic Presage Insights disclosed in the consent screen, README and Data panel as something Degup cannot turn off | Matches the SDK privacy policy | If Presage adds an Insights switch, turn it off and update the text |
| 8 | Nothing is stored by default; the API key is kept with Electron `safeStorage` | Consent screen promises only what the code does | None |
| 9 | Fixtures are derived numbers only; no images or video of anyone in the repo | Biometric video stays off git | None |
| 10 | `@smartspectra/node-sdk` pinned to exactly `3.4.0` | The integration was tested against that version | Bump with a full gate run |
| 11 | One `metrics` listener that fans out inside the app | A second SDK listener replaces the first | None |
| 12 | Live, replay and simulation sources share one interface (`src/sumber/`); game logic in `src/core/` has no DOM or SDK | The same game can be tested on recorded and simulated numbers | None |
| 13 | All UI text in `lang/en.json` and `lang/ms.json` (same keys); tunable values in `config/app.json` | English and Malay from day one; values change without code edits | None |
| 14 | A word list test (`tests/kata-larangan.json`) blocks clinical-sounding wording in the UI and public docs, with a narrow allow list for the required consent text | Degup is a game, not a health product | Add a key to the allow list only with a new entry here |
| 15 | Animations use transform and opacity only | Animated filters crash some GPU and WebKit paths | None |
| 16 | Built-in demo recorder | Makes the demo video reproducible | Use the OS recorder |
| 17 | MIT licence | Simple reuse | None |
| 18 | Internal Malay notes are not tracked in the public repo; public measurements live in [`MEASUREMENTS.md`](MEASUREMENTS.md) | Reviewers read English; internal paths do not belong in a public repo | Track the notes again |
| 19 | The demo video is cut by a script ([`scripts/video/sunting.mjs`](../scripts/video/sunting.mjs)): scenes, burned English captions, `.srt`, end card and loudness come from one storyboard table and [`config/video.json`](../config/video.json) | The same edit can be rebuilt when a number or the narration changes, without editing by hand | Edit the video by hand |
| 20 | A browser Simulation page ([`docs/sim/`](sim/)) is the same renderer bundle on a browser bridge ([`src/web/`](../src/web/)): Simulation source only, the SDK module swapped for a stub at build time, no camera, no API key, settings in `localStorage`. A test fails if the committed bundle differs from a fresh build | Reviewers without Windows or a key can try the flow; it never claims a live signal | Delete `docs/sim/` |
| 21 | Honest score (K1): "Some sense" needs R ≥ 0.45 as well as p < 0.05, and a round with fewer than 20 taps or under 30 seconds of taps gets "Too few taps to tell"; each band has one plain sentence; Simulation says it has no real beat to feel | A steady rhythm that feels nothing reached "Some sense" in about half of rounds under the old rule ([`MEASUREMENTS.md`](MEASUREMENTS.md)) | Set `ketukan_min` and `rentang_min_s` to 0 and drop `r_min` in `config/app.json` |
| 22 | Pause hints tolerate flicker (K2): a "no face" or "more than one face" code pauses only after 1.5 s, and the pause ends only after 1 s without one; motion, light, frame-rate and chest codes show a hint without pausing; hint text changes at most once a second; the code lists live in [`config/app.json`](../config/app.json) and are checked against the SDK `ValidationCode` enum | Real cameras flicker between codes several times a second; pausing on every code kept restarting the Ready countdown | Set both times to 0 and move every code to `kritikal` |
| 23 | The owner laptop kit is rebuilt from tag `v0.9.1` (K4), so a session run now uses the honest score (21) and the flicker-tolerant hints (22). Only one kit stays in the owner drop folder. A recording already made with the older `v0.9.0` kit still counts: the app log names the kit commit, and any frame that shows a result sentence since removed is cropped or cut from the final video | The owner sits down once; an old kit would record behaviour the repository no longer has, but throwing away a finished session would cost more than one cut | Rebuild the kit from any later tag with `scripts/kit/bina-kit.sh <tag>` |
| 24 | The local diagnostic log now keeps a short error message, not only the code: error name, code and first line, cut to a set length, with the user home folder replaced by `~` and the API key removed. The start-error screen shows the same short text on a small "Details" line, and camera errors name the likely cause (blocked by system privacy settings, used by another app, no camera, chosen camera missing). Still no key, no image, no camera frame in the log. Reason: the owner laptop run is the first Windows run with a real camera and may be the only one, so the log has to say why it failed. |
| 25 | "Too few taps to tell" shows no score number (L2): the reveal, the result card and the PNG card show "No score" or a dash with the band, and when some taps fell outside two clear beats the sentence names both counts ("12 of your 13 taps…") | 12 close taps gave a large "95 /100" above the "Too few taps to tell" pill; R from a few taps in a row is nearly always high, so the number contradicted the pill | `git revert` the L2 commit; band thresholds in `config/app.json` are unchanged |
| 26 | The owner laptop kit is rebuilt from tag `v0.9.2` (L3), so a session run now writes the short error details (24) and shows "No score" for too few taps (25). Only one kit stays in the owner drop folder. A recording already made with `v0.9.1` or `v0.9.0` still counts: the app log names the kit commit | If the first Windows run fails, the log and the Details line have to say why; a round with too few taps must not show a score on camera | Rebuild the kit from any later tag with `scripts/kit/bina-kit.sh <tag>` |
| 27 | Frames are scaled down before they reach the SDK (`src/renderer/kamera.ts`, `config/app.json` `sdk.bingkai_sdk`): the long side is capped at 640 px by default and the frame timestamps are kept. The demo recording was made on a server with no GPU, from the owner's phone video used as the camera, with the cap at 360 px and `--force-prefers-reduced-motion` | The SDK renderer loop draws and copies every frame as full RGBA on the renderer main thread. Measured on 23 Nov: a camera that delivers 1280-wide frames, or a machine with no GPU, feeds the SDK about 21 fps, which gives validation code 11 and then SDK error 8 within 10 s. With smaller frames the same run reached the result screen with no SDK error | Set `sdk.bingkai_sdk.sisi_panjang_maks` to 0 in `config/app.json`; the camera stream then goes to the SDK untouched |

Credit: the "renderer owns the camera, main owns the window and permissions" pattern follows the official SmartSpectra
`electron-quickstart` sample.
